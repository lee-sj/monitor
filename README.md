# monitor

운영 중인 웹 서비스들이 잘 돌아가고 있는지 자동으로 점검하고, 그 결과를 기록해 두는 프로젝트입니다.
사람이 매번 직접 들어가 확인하지 않아도, 정해진 시간마다 알아서 확인하고 문제가 생기면 알려 줍니다.

## 어떻게 동작하나요?

- 한 시간에 한 번씩 점검 대상 서비스에 접속해 상태를 확인합니다.
  다만 자동 실행 환경의 특성상, 실제 점검 시각이 예정보다 몇 시간 늦어지는 경우도 있습니다.
- 점검 결과는 매번 기록으로 차곡차곡 쌓입니다.
- 점검 대상은 두 종류로 나뉘며, 종류마다 확인하는 내용과 문제를 알리는 방식이 다릅니다.

### 1. 서비스 접속 점검

웹사이트가 접속되는지, 얼마나 빨리 응답하는지 확인합니다.

- **정상**: 20초 안에 정상적으로 응답한 경우
- **느린 시작**: 응답은 했지만 20초 넘게 걸린 경우.
  오랫동안 아무도 접속하지 않아 서버가 잠들어 있다가, 점검 접속으로 다시 깨어났다는 뜻입니다.
- **장애**: 최대 90초를 기다리고 여러 번 다시 시도해도 접속되지 않는 경우

장애가 생기면 자동으로 알림 기록이 만들어지고, 서비스가 복구되면 알림도 자동으로 종료됩니다.
느린 시작은 참고용으로 기록해 두며, 담당자가 확인한 뒤 직접 정리합니다.

### 2. 자동 작업 점검

서비스 안에서 주기적으로 돌아가야 하는 자동 작업이 제때 잘 수행되고 있는지 확인합니다.

- **정상**: 자동 작업이 제때 성공하고 있는 경우
- **멈춤**: 자동 작업이 일정 시간 이상 성공하지 못했거나, 확인 자체가 되지 않는 경우

작업이 멈추면 자동으로 알림 기록이 만들어지고, 작업이 다시 돌아가면 알림도 자동으로 종료됩니다.

현재 점검하고 있는 자동 작업은 다음과 같습니다.

- **입찰공고 자동 수집**: 마지막 수집 성공 후 3시간이 넘도록 새로 성공하지 못하면 '멈춤'으로 봅니다.
- **사전 규격 자동 수집**: 위와 같은 기준으로 확인합니다.

## 상태 페이지

점검 결과는 누구나 볼 수 있는 웹 페이지로 공개됩니다.

- 주소: https://lee-sj.github.io/monitor/
- 서비스 접속 점검과 자동 작업 점검이 구역별로 나뉘어 있습니다.
- 서비스별 현재 상태, 정상 비율 같은 통계, 최근 72번의 점검 결과, 문제가 있었던 기록을 한눈에 볼 수 있습니다.
- 새 점검 결과는 보통 몇 분 안에 페이지에 반영됩니다.

## 서버가 잠들지 않게 하는 방법

일부 서비스는 한동안 접속이 없으면 서버가 잠드는데, 잠든 서버는 다음 접속 때 깨어나느라 응답이 많이 느려집니다.
이를 막기 위해 각 서비스가 5분마다 스스로에게 접속해 깨어 있는 상태를 유지합니다.

이 프로젝트는 그 장치가 제대로 작동하는지 지켜보는 보조 역할을 합니다.
서버가 잠들어 있던 흔적(느린 시작)을 발견하면 기록으로 남기고, 점검 접속을 통해 서버를 다시 깨워 줍니다.

## 점검 대상 추가

점검 목록에 서비스 이름, 접속 주소, 점검 종류(접속 점검 또는 자동 작업 점검)를 한 줄 추가하면 다음 점검부터 함께 확인합니다.
점검 결과의 세부 내용은 기록하지 않지만, 등록한 접속 주소는 외부에 공개된다는 점에 유의해 주세요.
